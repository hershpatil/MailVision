1. Application Overview & Purpose

MailVision is an email security and spam classification platform designed to identify unwanted, deceptive, and malicious communications. The application utilizes a dual-engine architecture combining supervised Machine Learning (Multinomial Naive Bayes trained with TF-IDF vectorization) and deterministic heuristic rules (evaluating suspicious links, urgent phrasing, financial credential requests, and scam indicators).

MailVision is built to empower users with actionable security intelligence about their incoming messages while strictly respecting user confidentiality and minimizing data collection.

2. Google OAuth 2.0 Sign-In & Permissions
Google OAuth 2.0 Authentication

MailVision offers an optional Google OAuth 2.0 integration that allows you to connect your Gmail account securely. Authentication is performed directly on Google's secure authorization servers. MailVision never receives, sees, or stores your Google account password.

Gmail API Read-Only Permission Scope

MailVision requests access strictly to the following restricted Google OAuth scope:

https://www.googleapis.com/auth/gmail.readonly
Strict Read-Only Enforcement:

MailVision has no permission, no capability, and no programming logic to send emails, create drafts, delete messages, modify inbox content, mark messages as read, or modify labels or settings in your Gmail account. We read only message metadata and content necessary to calculate spam probabilities on demand.

3. On-Demand Scanning & Model Processing
On-Demand Execution (No Background Polling)

MailVision operates strictly on demand. The application does not continuously monitor your inbox, does not run background listening jobs, does not register persistent webhooks, and does not scrape messages when you are not using the application. Inbox scanning is initiated solely when you explicitly click the "Scan Inbox" button.

Limited Batch Size (Latest 5 Emails)

When you trigger an on-demand scan, MailVision retrieves only the latest 5 emails (or configured batch size) from your Gmail primary inbox. You may optionally page through subsequent batches on demand.

In-Memory Machine Learning Classification

Each fetched email's subject and body text are combined and processed entirely in temporary server memory by our local spam classification model. The text is analyzed for vocabulary frequency, phishing patterns, URL structures, and high-risk terms. Once the classification verdict, confidence level, and indicator list are computed, the structured results are returned directly to your browser for display.

4. Data Collection, Storage, Retention, and Deletion

Based on a transparent review of our codebase, here is exactly what data is stored, what is never stored, and how it is retained or deleted:

Data Category Current Implementation Behavior Retention & Deletion Policy
Email Content & Attachments Never Stored Subject lines, bodies, sender addresses, and email text are processed strictly in volatile memory. Not saved to any database or persistent disk. Exists only in volatile memory during the active HTTP request.
OAuth Tokens & Credentials Encrypted at Rest Access and refresh tokens are stored in the gmail_tokens table in encrypted form. Retained while your account is connected. Permanently deleted immediately when you click Disconnect Account.
Prediction Metrics (Audit Log) Anonymous Metadata Logs timestamp, classification verdict (SPAM/HAM), confidence %, and token/URL counts. No raw email text. Retained in the predictions table. Can be wiped at any time by the user via the Clear History button.
User Accuracy Feedback Optional Feedback Stores Gmail message ID, anonymous session ID, classification, and user choice (Correct/Incorrect). Stored in scan_feedback to evaluate heuristic efficacy. Contains zero email text or user identities.
How to Delete Your Data
  • Disconnecting Your Gmail Account: You can disconnect your Google account at any moment by clicking the "Disconnect Account" button in the Gmail dashboard. This action immediately invokes our disconnection handler (/gmail/disconnect), which permanently purges your session record and encrypted OAuth tokens from our database.
  • Clearing Prediction History: You can purge anonymous prediction logs at any time from the Audit Log page (/history) by clicking "Clear History" (/api/history/clear).
5. OAuth Token Security & Encryption at Rest

MailVision treats authorization tokens with strict cryptographic safeguards:

Authenticated Symmetric Encryption

Stored OAuth access tokens and refresh tokens are protected using an Encrypt-then-MAC authenticated encryption scheme (HMAC-SHA256). Each token is encrypted using a cryptographically random 16-byte initialization vector (IV) and verified against tampering before decryption.

Secure Session Isolation

Tokens are mapped strictly to an ephemeral, randomly generated session ID stored in an HttpOnly, SameSite=Lax secure cookie. OAuth authorization flows are guarded against Cross-Site Request Forgery (CSRF) using cryptographically signed HMAC state tokens.

7. User Consent & Revocation of Gmail Access

Connecting your Gmail account requires your explicit informed consent via the official Google OAuth consent screen. You retain full control over this connection and may revoke it at any time through either of the following methods:

  1. Within MailVision: Navigate to the Gmail Inbox Scanner page and click Disconnect Account. This permanently removes your encrypted tokens from our database.
  2. Directly via Google Account Security: You can manage or revoke third-party app access directly through your Google Account settings by visiting:
    https://myaccount.google.com/permissions

Once revoked via Google, MailVision's stored tokens will be instantly rejected by Google APIs and will no longer be capable of querying your inbox.
